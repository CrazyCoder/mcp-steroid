## 0.116

`steroid_ui` now shows which controls a panel or window cuts off, and makes room for them with a step. It reaches the main menu in every way the IDE shows it, including a menu outside the IDE window. A scenario replay puts back what its steps changed, lays the IDE out the same way before every run, and skips an IDE it does not apply to.

### Cut controls and room for them

- The snapshot marks a control past the edge of its panel or window with `[outside]`, one that is partly cut with `[clipped]`, and a label cut to its width with `[truncated]`. A tree, list or table whose rows are wider than its view says so above its rows.
- Each window ends with a `layout:` line for each tool window or window that cuts controls, or for a tool window narrower than its header. The line names the step that makes room, such as `{"action":"toolwindow","id":"Project","width":"fit"}`.
- A click on a partly cut control presses the part that shows. A click on a control past an edge fails and names the step that makes room, and also the action behind the control when it has one, which a `run` step takes.
- `{"action":"toolwindow","id":"Project","width":"fit"}` sizes a side tool window, and `"height"` a bottom one, in logical pixels or `fit`. `fit` gives the tool window the size its header needs, and the size of its content up to 40% of the IDE window. It measures after the header toolbar has filled in, which takes a moment in a JetBrains Client.
- The `window` step sizes a window. `"maximize":true` fills the screen with the IDE window, `false` restores it, and a `width` and `height` set its size. `{"action":"window"}` alone fills the screen with the IDE window, or grows a dialog to show its content. The window stays on its screen and above its minimum size, and the report gives the size before and the screen's usable area.
- `{"action":"expect","layout":true}` checks that the topmost window has no `layout:` line. With a target, it checks that no control under the target is cut.

### Main menu

- `{"action":"menu","path":"View > Appearance > Status Bar"}` runs a main menu item whichever way the IDE shows the menu: merged into the main toolbar with menus folded into the Main Menu button, under that button, as a menu bar, or outside the IDE window in the macOS screen menu bar or a Linux global menu, where no click reaches it.
- A checkable item's report gives its state before and after. A path to a submenu lists its items with their action IDs, shortcuts and states, and `{"action":"menu"}` lists the menus and marks the folded ones.
- `{"action":"check","path":"..."}` and `uncheck` run a checkable item only when its state differs.
- `{"action":"menu","mode":"merged"}` sets how the main menu shows: `merged`, `hamburger` or `toolbar`. Only the new UI on Windows and Linux has this setting.
- The snapshot of the IDE window ends with a `menu:` line when menus are folded into the Main Menu button, under it, or outside the window.
- The macOS screen menu and the Linux global menu were not tested on those systems. The menu step uses the platform's own check for the macOS screen menu.

### Scenarios

- A replay of a whole scenario puts back what its steps changed, after its cleanup and last change first. This covers every kind of `set`, main menu items and the menu mode, a tool window's tab, size and visibility, the IDE window's size, and files that `write` changed or created. In Split Mode, each restore runs on the side where its step ran. A run stopped early with `to_step` restores nothing, and ends with an `undo:` line that lists the steps that would.
- A `setup` block holds settings, the menu mode, the IDE window's size, tool window sizes and any other steps. It runs before every replay, including one that starts at a later step. When a setup step fails, the verdict is `BROKEN at setup step N` and no step runs.
- `setup.layout` sets what happens when a step opens a window, or shows or sizes a tool window, that cuts controls. `note`, the default, adds the `layout:` line to the step's report. `check` also counts it as a failed soft check. `auto` makes room with the step the line names. It also makes room in the IDE window before the first step and before a click on a control past an edge, which it then tries again.
- `requires` states the build range, product codes, plugins, operating systems, and Split Mode or a regular IDE that a scenario needs. On another IDE the verdict is `SKIPPED` with the reasons, not `FAILED`.
- A screenshot's report, and a `<name>.json` file next to the picture, give the window size, the screen and IDE scale, the theme, the editor font, the build and the OS. These are the settings that make two pictures of the same state differ.
- `{"action":"write","file":"...","delete":true}` deletes a project file.
- `steroid_fetch_resource` with `mcp-steroid://ide/ui-scenario-schema` returns the JSON schema of the scenario format. A test keeps the schema in step with the parser, and scenario files can name it in `$schema`.
