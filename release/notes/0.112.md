## 0.112

This release keeps agents from freezing the IDE with inspections, tells them at once when the IDE freezes or logs errors anyway, and stops the work of a call they give up on.

### Inspections that cannot freeze the IDE

- `steroid_refactor` has an `inspect` op. It runs the inspections as Code | Inspect Code does, in a background task that gives way to the user's edits, over a file, a directory or the whole project: `{"op":"inspect","file":"src/Foo.kt"}`. It lists `path:line: [short name] SEVERITY description` from weak warnings up, and `"all": true` adds information-level problems. `"inspection"` limits the run to short names, comma-separated. The list stops at 200 lines with a count per inspection, and a run past 5 minutes stops and says the list is incomplete.
- `runInspectionsDirectly` in scripts and the `fix` op of `steroid_refactor` use the same engine. `runInspectionsDirectly(file, inspections = setOf("ShortName"))` runs only the named inspections.
- An inspection that crashes is reported, in `failedTools` for scripts, and the file is inspected again without it, so one broken inspection no longer hides the results of the others.
- Problems found in injected code, such as SQL in a string, are reported at the host file's path and line.
- The prompts warn against `InspectionEngine.inspectEx` in scripts: its worker threads ignore cancellation and keep the read lock, which froze IDEs whose TypeScript service then waited for a write action.

### Freeze and error notices

- When the IDE's UI stops responding, after the platform's own 5 s threshold, every tool result starts with an `IDE FREEZE` notice. It says whether the UI thread waits for a lock or runs code, and names the threads holding the lock, the `steroid_execute_code` execution among them, and the folder of the IDE's thread dumps. A call still waiting 2 s after the freeze is reported is answered with the notice instead of hanging; it keeps running in the IDE. The end of the freeze is reported once.
- A `steroid_execute_code` script that holds a read lock the frozen UI waits for is cancelled.
- Errors the IDE logs between calls, the ones behind its red error balloon, are listed before the next result in a few lines: one line per kind of error, at most three, with the path of `idea.log` for the full traces. Errors a `steroid_execute_code` run already listed are not repeated.
- In Split Mode both notices say which process they are about, the backend or the JetBrains Client, and each error is reported once.

### Cancelled calls stop in the IDE

- A client that cancels a call with `notifications/cancelled`, as Claude Code does when a background task is stopped, now stops the work in the IDE, and the call gets no response. Closing the connection stopped it already.
- After an IDE restart, a client that keeps sending its old session id stays in one new session, so notices are not repeated on every call.
