## 0.109

### Split Mode and Remote Development

- MCP Steroid Plus works in Split Mode, where a JetBrains Client shows the windows and a Remote Development backend holds the project. Install the plugin on both sides at the same version. Agents connect to the client's endpoint: project work, such as `steroid_list_projects`, `steroid_open_project` and `steroid_execute_code`, is forwarded to the backend, while `steroid_list_windows`, `steroid_take_screenshot` and `steroid_input` run in the client, where the user sees the windows. `project_name` keys come from the backend and every tool accepts them.
- `steroid_execute_code` takes a `side` parameter. Scripts run on the backend by default; `side=frontend` runs them in the client, for its windows, popups, tool window visibility and focus. In a regular IDE both values run in the same process.
- `steroid_list_windows` lists each process it spoke to in `backends[]` with a `role` of `monolith`, `frontend` or `backend`, so an agent can tell which setup it is connected to.
- A new article, `mcp-steroid://skill/split-mode`, tells agents which side each tool and API runs on, how backend editors, dialogs and Settings pages reach the client, and when to use the backend's own endpoint. The backend keeps that endpoint for when the client cannot reach it.
- When the backend is gone, the screenshot, input and window tools keep working in the client and answer quickly, and forwarded calls fail with an error that names both possible causes.
- The `mcp-steroid://ide/ui-driving` recipe builds its UI model in a JetBrains Client. It failed there with "must not be requested from main classloader", and then with "Invoker is not registered".

### Clicks that land where a real click would

- `steroid_input` clicks reach controls in Settings. The Settings window keeps a visible glass pane over its controls, and every click went to the pane. A click is now delivered to the window as a mouse move, press, release and click, and the IDE picks the component the way it does for real input.
- Popup rows and menu items can be clicked. A list popup selects its row when the pointer moves over it and ignores the first move it sees, so a click now approaches the point with two moves.
- A click at screen coordinates goes to the window on top at that point, such as a popup over the frame, instead of the window named by `window_id`. The response names the window the click went to.
- `steroid_list_windows` gives every window a `project_name`, dialogs included, so `steroid_take_screenshot` and `steroid_input` can reach a dialog such as Trust Project.
- On a HiDPI display, `steroid_take_screenshot` reports the image scale when the image is larger than the window's logical size. Divide positions read from the image by it before passing them to `steroid_input`.

### IDE exceptions in script output

- IDE exceptions logged while a script runs are printed as short summaries: the plugin, the first line of the message and the top frames. The full stack traces go to `ide-exceptions.txt` in the execution folder. A repeated exception takes one line, and so does every distinct exception after the first five. Exceptions logged in a burst are all kept, not only the last one.

### Opening projects

- `steroid_open_project` returns while a dialog of the open, such as Trust Project, waits for an answer, and says so. It waited for the answer, which the agent calling it could not give.
- `steroid_open_project` works on IntelliJ IDEA 2026.3 after a project was closed while the IDE window was not focused. It failed with HTTP 500. An open that fails or is declined is reported as an error.
- A project opened as `c:/...` and as `C:/...` gets one `project_name`. Projects opened from a lower-case drive path get a new `project_name` once.

### Other fixes

- A cancellation raised inside the IDE while the MCP request is still active returns an error result with its message. It surfaced as HTTP 500 with an empty body.
- The plugin verifier checks IntelliJ IDEA 2026.3 EAP as well.
