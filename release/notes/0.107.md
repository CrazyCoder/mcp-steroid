## 0.107

### Drive IDE UI from one script

- A new recipe, `mcp-steroid://ide/ui-driving`, teaches the UI model that JetBrains IDEs bundle in the Performance Testing plugin. `XpathDataModelCreator` turns the showing Swing tree into a DOM with accessible names, tooltips and painted text, such as tree and list rows, tabs and editor text, which a script queries with XPath. One `steroid_execute_code` call can open a dialog, find its controls by what they show, type, click, check the result and close it, instead of a screenshot and a `steroid_input` call per step. A compact snapshot prints each named control with screen coordinates that `steroid_input` accepts as `click:left@screen:<x>,<y>`.
- The recipe covers the traps a normal IDE sets. Building the model fails with "Invoker is not registered" until the JMX test-driver extension is dropped. Key events posted to the event queue are dropped while no component has focus, so input goes through `Component.dispatchEvent`, which also works with the IDE in the background and never moves the mouse. A dispatched Escape does not close a popup, so popups and dialogs close through `PopupUtil` and `DialogWrapper`. The plugin's default robot moves the real mouse, so the recipe does not use it for input.
- The IDE examples overview lists the recipe, and the `steroid_execute_code` description points to it for dialogs a script opens itself.
