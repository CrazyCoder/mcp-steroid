## 0.106

### No more waiting behind modal dialogs

- With a modal dialog open, every `steroid_execute_code` call waited 30 s before it compiled, because the pre-run VFS refresh is held back until the dialog closes. The refresh is now skipped while the IDE is modal, and a trivial call under a dialog returns in under a second.
- The script timeout bounds the call. A script blocked in a dialog it opened, or in any thread-blocking call, kept the tool call open until it returned ([jonnyzzz/mcp-steroid#465](https://github.com/jonnyzzz/mcp-steroid/issues/465)). Two seconds after the deadline, Steroid writes a thread and coroutine dump to `timeout-dump.txt` in the execution folder ([jonnyzzz/mcp-steroid#215](https://github.com/jonnyzzz/mcp-steroid/issues/215)) and closes the dialogs opened during the run. A script that still does not stop is left running, and the call returns with a message that says so. Dialogs that were open before the script started are never closed.
- Every dialog Steroid closes is named in the result: `Closed modal dialog '<title>' (Cancel).`
- The `steroid_execute_code` description says what waits under an open dialog and how to read, press and open dialogs without blocking.

### Editor highlights that do not time out silently

- `waitForEditorHighlighting` and `getHighlightsWhenReady` timed out on a file the daemon had analyzed before, and returned an empty list that read as a clean file. The wait now restarts the analysis for the file once when no pass completes within a second.
- On a timeout, the result carries a warning, naming the inactive project window when that is the cause (the IDE analyzes only the active window), and `getHighlightsWhenReady` returns the last analysis. A file that is not open in an editor gets a warning that says how to open it.

### Recipe fixes

- The Gradle import recipe reports a failed import. A broken build script still reaches `onFinalTasksFinished`, so the recipe compares the last import with the last successful one. It also notes that a dependency that cannot be downloaded becomes a library with no class roots instead of a failed import.
- Recipes that report inspection results render the message with `ProblemDescriptorUtil.renderDescriptionMessage` instead of printing the raw template, so they show `Function name 'foo' ...` instead of `Function name <code>#ref</code> ...`.
- The Maven and Gradle recipes no longer say every call is cancelled after about 60 s. That is a client default, which a `timeout` on the server's MCP entry lifts; scripts default to 600 s.
- The `runInspectionsDirectly` documentation says it runs local inspections only, so unused-symbol warnings come from `getHighlightsWhenReady`.
- The context API article says `writeAction` can run as a background write action, so `WriteCommandAction` needs the EDT.
