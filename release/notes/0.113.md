## 0.113

`steroid_ui` can now replay a written IDE procedure and report a verdict. The procedure can reproduce a bug, check a feature, or capture a screen. Agents also hear when an editor banner says the project is not set up.

### Scenarios: repeatable IDE procedures

- A scenario is a JSON file with a title, steps, and cleanup steps. `steroid_ui` replays it with the `scenario` parameter, or replays a part of it with `from_step` and `to_step`. The cleanup steps always run.
- The replay ends with a verdict. PASSED means every step held. FAILED means a check did not hold, and BROKEN means a step could not be done. A scenario with bug checks reads REPRODUCED or NOT REPRODUCED. A replay on another IDE build says so.
- `steroid_ui` records the steps of every call to the task's recording file. The recording names controls by what the user sees: names, captions, row text, Settings page ids, and full option names. A recording is the first draft of a scenario file.
- The `mcp-steroid://ide/ui-scenarios` resource documents the format, the steps, and the practices, which follow Playwright. The tool description points to it.

### New steroid_ui steps

- `expect` checks a control's state, value or text, a tree or list row, a window, a file's text, the caret, a notification, an editor banner, or an IDE error. It retries until the check holds or its timeout passes. `"not"` inverts the check, `"soft"` records a failure and continues, and `"bug"` marks the check that fails when the bug is present.
- `get` and `set` read and change configuration without a dialog, in milliseconds. They cover registry keys, advanced settings, the on/off options that Search Everywhere toggles, inspections of the current profile, and fields of persistent settings components by state name. Each `set` reports the value before and after.
- `settings` opens Settings at a page by id, path or name. If Settings is already open, it switches to that page.
- `toolwindow` shows a tool window and selects a tab, or hides the tool window.
- `write` creates or replaces a project file through the IDE's documents.
- `code` runs a Kotlin body, as `steroid_execute_code` does.
- `perf` runs Performance Testing playback commands. The IDE's command list checks each command before it runs.
- `screenshot` saves a picture of the topmost window, or of the window that holds its target, in the call's execution folder.
- Any step takes `"intent"`, and its report repeats it. A later agent can repair a broken step from what it was for.
- `select` and the other row steps wait for their row. They find a row in a tree that is still filtering to a search typed in the step before.

### Name matching

A name now matches without a caption's trailing colon and with either spelling of an ellipsis. `Show line numbers` finds the checkbox `Show line numbers:`, and `Settings...` finds `Settings…`. A checkbox and the combo box it captions can share a name. The control whose own name it is now wins, and the step is no longer ambiguous.

### Editor banner notices

An open editor can show a warning or error banner, such as "Module JDK is not defined". The next tool result then starts with an `EDITOR BANNERS` notice. The notice has one line per banner with its links and the files that show it, and tells how to click a link with `steroid_ui`. Each session hears about a banner once, and again if it goes away and comes back.

### Split Mode

In a `steroid_ui` call through the JetBrains Client, a step with `"side": "backend"` runs on the backend. Steps that need the project, such as `write`, `code`, `goto` and checks on files, go to the backend without a side. One scenario can therefore cover both sides. A relative scenario path resolves against the backend's project folder.

The Split Mode resource explains why the JetBrains Client disables MCP Steroid on both sides when the two sides run different versions, and how to recover.
