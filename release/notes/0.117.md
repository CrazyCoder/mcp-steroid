## 0.117

`steroid_ui` now reports the code each step changes, and a scenario can check that code as a test does. Tool results report the builds and runs that failed. Refactorings, context actions and generators run through their popups and dialogs as a person runs them, in any language.

### Code changes

- A step that changes project files ends with them, such as `changed src/main/java/demo/App.java (+5 -1)`, and the response ends with the diff of the whole call under `code changes:`. It covers refactorings, generators, typing, and files created, deleted or moved. Build output, `.idea` and edits made outside the IDE are left out.
- `{"action":"get","changes":true}` gives the whole diff when the summary is cut.
- `{"action":"expect","changed":["src/App.java"]}` checks exactly which files changed, and `[]` checks that none did.
- `{"action":"expect","file":"src/App.java","diff":"-int total = count;\n+int total = sum();"}` checks lines of the file's diff, compared without indentation. Without `file`, it checks the diff of every file.
- `{"action":"expect","file":"src/App.java","golden":"expected/App.java"}` checks that the whole file equals a golden file. A mismatch shows the diff between them.
- A replay of a whole scenario writes back each file its steps changed and deletes the files they created. Local History gets a label before the steps, `steroid_ui: before "<title>"`, to revert to by hand.
- Split Mode does not track the steps' code changes. There, `changed`, `diff` and `get changes` fail and name the `expect` on `file` that checks a file's text.

### Failed builds and runs

- Tool results start with a `BUILD FAILED` notice when the IDE's build, a Maven or Gradle build, or a Maven or Gradle sync failed since the previous call. It names the first errors as `path:line: message`.
- A `RUN FAILED` notice does the same for an application, a test or a build tool task that exited with an error code, with its last error lines. A run the user stopped does not count.
- `{"action":"get","builds":true}` lists the recent builds and syncs with their outcomes and first errors.
- `{"action":"get","console":"App","lines":40}` reads the last lines and the exit code of the latest run named App, and `""` reads the latest run. The output stays readable after its tab closes. Error lines start with `! `.
- `{"action":"expect","console":"App","contains":"total: 5"}` checks what a run printed.

### Editor actions

- The new guide `mcp-steroid://ide/editor-actions` shows how to list what applies at the caret, run context actions, the context menu, Refactor This and Generate, drive their dialogs, and read the code they changed. It lists the common action IDs.
- Rows of a popup such as Refactor This or Generate show the action ID each one runs, as `action=ChangeSignature`, which a `run` step takes.
- `run ShowIntentionActions` waits for the editor's analysis, so the Alt+Enter popup lists every context action and quick fix.
- `run $Undo` names the command it undoes, such as "Undo Typing". When the caret is away from the change, the first Undo only moves the caret back to it, and the report says so.
- A click on a dialog's default button, such as Refactor or OK, waits for that dialog to close. Before, a refactoring that showed a progress window or ended a table edit first was reported with its dialog still open.
- A click on a submenu, such as Refactor in the editor's context menu, waits for its items and says how many it shows. Before, the report said nothing had changed.
- `close` closes a context menu or a main menu with its submenus. Before, it failed on them.
- `fill` with a label's name types into the field, not the label, when both have the name.
- An HTML pane, such as an error hint, shows its text as `value=` rather than its markup and style sheet.
- The snapshot diff leaves out the gutter, the breadcrumbs, the text of a file's editor, and times that only aged, such as "(3 minutes ago)".
