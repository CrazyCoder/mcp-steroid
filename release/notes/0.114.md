## 0.114

`steroid_ui` can now read and change option tables, and check the editors the user sees and the lines the IDE logs. It tells agents when a JetBrains Client and its backend disagree about the open editors. Several steps that failed or reported the wrong thing in Split Mode now work.

### Option tables

- A snapshot lists a table row's other cells after `|`, such as `#0 Hard wrap at: | 120`, and a checkbox cell as `[x]` or `[ ]`. Tables such as Code Style and Registry showed only their first column before.
- `fill` with a `row` sets that row's value cell through the cell's own editor: `{"action":"fill","class":"TreeTable","row":"Hard wrap at:","text":"90"}`. A checkbox cell takes `true` or `false`. A value the cell does not take fails the step and leaves the cell as it was.
- `expect` with a `row` and `value`, `contains` or `matches` checks the row's other cells.

### Editors, logs and files

- `{"action":"get","editors":true}` lists the open editors of each side. On a Remote Development backend it also lists the backend's record of each JetBrains Client session, with a count for a file that has more than one editor. Through a Client it adds a `mismatch:` line for each disagreement between the two.
- `{"action":"expect","editor":"src/A.kt","is":"focused"}` checks that the user sees a file's editor: `visible`, `focused`, or `hidden` for none.
- `{"action":"expect","log":"Opening remote editor for file=A.kt"}` checks for a line in this side's `idea.log` written since the run started. MCP Steroid's own lines do not count, because they repeat the call's arguments.
- `{"action":"set","log":"#com.jetbrains.rdserver.fileEditors","value":"debug"}` sets a debug log category, as Help | Diagnostic Tools | Debug Log Settings does. It takes `trace`, `debug`, `all`, or `default` to remove the level. `get` reads the level.
- `{"action":"get","file":"src/A.kt"}` gives a file's type, language, size and editor providers. On a backend it also gives how many editors each Client session has of the file.
- `"error": true` in an `expect` means any IDE error, as `""` does.

### Split Mode

- After steps that can open or close editors, a `steroid_ui` call through the JetBrains Client compares its editors with the backend's record. When they disagree, the result starts with an `EDITOR STATE` notice, once for each disagreement in a task. A Client that reconnects with a tab open can leave the backend with two editors of that file. The file then opens neither from the Project view nor from a navigation until its tab is clicked, and the notice names it.
- A `goto` that runs on the backend moves the focus to the Client's editor of the file, so the next step acts on that file. Before, the focus stayed where it was, and an action such as Reformat Code ran on the Project view. When the Client shows no editor of the file, the `goto` fails and names the tab to click.
- An `expect` on `error`, `notification` or `log` that runs on the backend counts from the start of the run. It counted from its own step before and missed an exception thrown a few steps earlier.
- `settings` and `toolwindow` wait for their page or tool window up to their timeout. Right after a Client connects, the backend's Settings pages and tool windows are not there yet, and both steps failed.
- A Client snapshot of a window the backend draws, such as a Rename dialog, notes that its steps need `"side": "backend"`. The snapshot alone showed an empty window.
- The Client's Project view tree has the name a regular IDE gives it, `Project structure tree`, so one step finds it in both. A tree row path also matches a row whose text continues after the name, such as the Project view root `mcp C:\work\mcp`.

### Fixes

- `steps` sent as a JSON array, not as a string, failed with a stack trace. Any string parameter now takes a JSON array or object as its text.
- `fill` into an IDE editor field kept the field's own selection. In a Rename dialog, which selects the name without its extension, `Cargo.lock.msrv` became `Cargo.lock.msrv.lock`, and the step reported success. `fill` now replaces the whole text and fails when the field holds other text.
- A report from the backend no longer includes the backend's keyboard focus, which is not where the user types in the Client.

### Scenario format

- The scenario format only grows. A released step, field, value or verdict keeps its name and meaning. Every MCP Steroid version replays every format 1 scenario written for it or for an older version. `mcp-steroid://ide/ui-scenarios` states the contract, and a test fails when a released form stops parsing.
- An older MCP Steroid that meets an unknown step or field says the scenario may come from a newer version. The error asks to update the plugin.
