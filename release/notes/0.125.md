## 0.125

This release ships the `devrig` CLI built from this repository, with its installers, next to the plugin. devrig installs and updates from this repository's releases instead of `devrig.dev`, and passes every tool parameter to the IDE.

### Install devrig from this repository

- Install or update devrig with `curl -fsSL https://github.com/CrazyCoder/mcp-steroid/releases/latest/download/install.sh | sh` on macOS and Linux, or `irm https://github.com/CrazyCoder/mcp-steroid/releases/latest/download/install.ps1 | iex` on Windows.
- Each release carries the devrig zip, `install.sh`, `install.ps1` and `version.json`. A running devrig reads `version.json` of the latest release and installs a newer release by itself.
- A devrig installed from `devrig.dev` keeps updating from there and has no `ui` or `refactor` command. Run the command above once to replace it, then restart your agent sessions.
- The plugin's Install devrig button and its "What is devrig?" links use this repository.

### devrig and the IDE

- devrig passes every parameter it advertises to the IDE. `steroid_ui` dropped `scenario`, `from_step`, `to_step`, `restore` and `output`, so a scenario replay through devrig ran as a snapshot; `steroid_execute_code` dropped `side` and `output`.
- The calls of one `devrig mcp` session share one IDE session, so a notice such as a freeze that ended or the errors the IDE logged is told once, not on every call.
- `devrig install plugin` no longer skips every IDE because JetBrains Marketplace has no build of MCP Steroid Plus. It asks each IDE it reaches to install the plugin, and first says to add the plugin repository `https://github.com/CrazyCoder/mcp-steroid/releases/latest/download/updatePlugins.xml` under **Settings | Plugins**, gear icon, **Manage Plugin Repositories…**. `devrig backend provision` gives the same steps.
- A boolean flag followed by another flag works: `devrig ui --restore --snapshot=none`.
- The installers register devrig in the home they install into, when `HOME` or `USERPROFILE` points somewhere other than the account's home.

### UI

- The `restore` parameter says what a scenario replay shares with it: a replay puts back what its steps changed, and closes the windows they opened only in its `cleanup`.
