## 0.119

`steroid_ui` saves pictures of a Settings page, menu or dialog with the controls that matter outlined and numbered, and one call can open the page, take the picture and put the IDE back. It also lists and switches themes. In Split Mode each agent session hears the backend's notices, and `run` steps work for actions such as ShowSettings on macOS.

### Pictures with highlights

![Editor > General > Appearance, cut to the page, with the breadcrumb and two options outlined and numbered](https://raw.githubusercontent.com/CrazyCoder/mcp-steroid/v0.119/release/notes/img/0.119-crop-page.png)

The picture above is one `steroid_ui` call: a `settings` step, then a `screenshot` with `"highlight":["breadcrumb",{"name":"Show line numbers"},{"name":"Show method separators"}]` and `"crop":"page"`, with `"restore": true`.

- A `screenshot` step takes `highlight`: controls by any locator, rows of a list, tree or table, or `"breadcrumb"`, the path above a Settings page. Each is outlined and numbered 1, 2, 3 in the given order, with an optional `label`. The badge sits beside the outline. Outlines of neighbouring rows keep a clear gap. A highlight out of view is scrolled into view first, and one that is not showing fails the step.
- `crop` cuts the picture to the Settings page (`"page"`), the highlights, the open menus (`"popups"`) or one control; `margin` sets the padding.
- `out` names the file: absolute in a call with steps, relative to the scenario file in a replay. It saves a PNG by default, or a JPEG for a `.jpg` path. When it replaces a PNG, the report says `unchanged` or how many pixels changed, so a replay of documentation pictures names the stale ones.
- A picture holds the menus and popups open above the window, and never reads the screen, so other applications do not show through.
- In Split Mode the JetBrains Client takes the picture. Highlights on a host Settings page, whose controls exist only on the backend, are found there.

### Framing and restore

- `"restore": true` on a call with steps closes the windows and menus its steps opened and puts back what they changed, as a scenario replay does, whether the steps passed or failed.
- `{"action":"set","theme":"Light"}` switches to an installed theme and waits until every window has repainted; `"sync"` follows the OS again. `{"action":"get","themes":true}` lists the installed themes. The restore puts the theme back.
- `{"action":"menu","path":"View > Appearance","show":true}` opens a main menu path and leaves it open for a picture, from the menu bar or the Main Menu button.
- `scroll` takes `"align":"top"` or `"center"` to place a control in its view, and its report ends with the control's screen bounds.
- A `window` step on Settings or a dialog records a restore of the size the IDE saved for its next opening, so a resize for a picture does not outlive the run.

### Split Mode and actions

- The backend keeps a session for each agent session of the JetBrains Client, so every agent hears the backend's notices once. Before, only the first agent heard them.
- A `steroid_ui` call with a step that runs on the backend passes on the backend's notices, such as `EDITOR ERRORS in the backend`.
- A `run` step executes the action without a made-up key event. On macOS, ShowSettings and other actions the application menu also offers disabled themselves for such an event.
- A `run` step that leaves an in-place template active says whether the step started it or it was active before.
