## 0.115

MCP Steroid reports when the IDE runs short of memory, and `steroid_ui` can read and check the IDE's memory. A scenario call replays a whole folder of scenario files. Programs that read a tool's result can ask for a versioned JSON result that later releases only extend.

### Memory

- When the IDE's garbage collector is overloaded, the next tool result starts with a `LOW MEMORY` notice. Slow calls are then likely memory pressure, not a freeze.
- The notice needs 5 overloaded-GC signals in 15 minutes, or one with more than 85% of the heap still in use after the GC. The platform's own low-memory warning uses the same throttle, so indexing alone does not trigger it.
- When less than half of the heap stays in use after a GC, the notice calls the pressure an allocation burst. Otherwise it suggests closing projects, or the IDE's Change Memory Settings action.
- `{"action":"get","memory":true}` reports the figures of the status bar's memory indicator: heap, direct buffers, non-heap pools, threads, memory-mapped files and the OS totals. It adds the heap in use after the last GC and the GC's share of the time since the previous report.
- `{"action":"expect","memory":"heap_after_gc","below":1500}` checks a figure against a limit, for a memory-leak or thread-leak fix. The figures are `heap_after_gc`, `heap`, `threads` and `gc_signals`.
- `heap_after_gc` runs a full GC before it measures. In an IDE started with `-XX:+DisableExplicitGC`, the check says that no full GC ran.
- In Split Mode, each side has its own heap. The notice names the side it comes from, and the steps read the side they run on.

### Scenario replay

- `scenario` also takes a folder, which replays every `*.scenario.json` under it, or a JSON array of files and folders.
- Each file replays as its own call would. The result starts with a count per verdict and one verdict line per file, followed by each file's report.

### Output contract for programs

- A call to `steroid_execute_code` or `steroid_ui` with `"output":"json"` gets exactly one text item. That item is a JSON object, version 1 of the contract. Without the parameter, the result is text for a model, as before.
- For `steroid_execute_code`, `stdout` holds only what the script printed, and `result` holds that output parsed when it is one JSON document. MCP Steroid's own lines go to `messages`, and exceptions and failures go to `errors` with their stack traces.
- IDE notices, such as an IDE error or a UI freeze, go to `notices` with their kind and Split Mode side. They never mix with the script's output.
- An error before the tool runs, such as an unknown project, also comes back as a JSON object. So does a call that a freeze holds up or that the IDE cancels.
- The contract only grows. A released field keeps its name, type and meaning, and a test fails the build when one changes. `mcp-steroid://skill/output-contract` documents every field.
